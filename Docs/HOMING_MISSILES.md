# 유도 미사일

MainPlay의 무작위 아이템 공급에 연결했다. 보라색 미사일 아이콘을 획득하면 그 위치에서 4발이 퍼져 나와 적을 추적하고, 접촉 시 작은 범위 폭발을 만든다. 획득 아이콘은 사용자가 제공한 `Assets/Main/04_Resource/Items/pickup_interceptor_missile.png`다. 표시 폭 1.4·획득 반경 0.7의 공통 획득물 크기를 사용하며, 플레이어와 기존 아이템 효과의 크기는 유지한다.

## 원작 참고와 미확인 수치

[iPhone AC의 원작 공략](https://iphoneac.com/tilttolive.html)은 iPhone판의 5발 발사, 유도, 착탄 폭발과 주변 적 처치를 설명하며 iPad판은 7발이라고 구분한다. [2010년 출시 리뷰](https://jeffsreviews.wordpress.com/2010/03/04/tilt-to-live-review-the-dawn-of-the-red/)도 5발 발사를 기술한다. 원작을 참고해 처음 5발로 구현했고, 현재 본편은 밸런스 조정으로 4발을 사용한다.

속도·회전 성능·폭발 반경·수명·발사 각도·표적 우선순위의 정확한 원작 내부 수치는 확인하지 못했다. 아래 수치는 현재 경기장에 맞춘 조정 가능한 초깃값이며 원작과 완전히 동일한 수치라고 주장하지 않는다. 표적 재탐색, 분산과 시간 만료 처리도 현재 구현의 명시적인 규칙이다.

## 현재 동작

- 획득 순간 4발이 방사형으로 발사된다. 비행 방향은 회전 속도 제한을 두고 표적 쪽으로 휘어진다.
- 예고 중인 적을 제외하고 활성 적을 추적한다. 빙결된 적도 표적과 처치 대상에 포함한다.
- 같은 묶음 안에서는 다른 탄이 추적하지 않는 가까운 적을 우선한다. 표적이 부족하면 같은 적을 추적할 수 있다.
- 표적이 죽으면 다시 탐색한다. 적이 없으면 현재 방향으로 계속 비행하며, 이후 나타난 적을 다시 탐색한다.
- 미사일과 적의 양쪽 이동 구간을 사용해 첫 접촉 위치를 찾으므로 빠른 비행에서도 적을 통과하는 문제를 줄인다.
- 접촉하거나 수명이 끝나면 그 위치에서 폭발한다. 폭발은 표시가 유지되는 동안 범위 내 적을 처치하고, 이미 처치된 적은 다시 점수를 주지 않는다.
- 획득 시 무적은 없다. 미사일이 모두 적을 제거하기 전까지 플레이어는 회피해야 한다.
- 재획득하면 새 4발을 추가하며 기존 탄과 폭발은 취소하지 않는다. 재시작 시 모든 탄·폭발·꼬리·효과음을 정리한다.
- 기존 세 아이템의 가중치는 유지하고 미사일 가중치 1을 추가했다. 현재 네 종류의 초기 가중치는 1:1:1:1이며 원작 확률을 확인한 값은 아니다.

## 조정 위치

`Assets/Main/06_Content/Items/HomingMissiles.asset`에서 조정한다.

| 항목 | 초깃값 |
| --- | --- |
| 발사 수 | 4발 |
| 이동 속도 | 초당 9 유닛 |
| 회전 속도 | 초당 540도 |
| 비행 수명 | 4초 |
| 미사일 접촉 반경 | 0.09 |
| 폭발 반경 | 0.75 |
| 폭발 유지 시간 | 0.22초 |

`HomingMissileEffect.prefab`은 미사일 이미지·배기 꼬리·착탄 프레임·효과음을 연결한다. 표현 오브젝트는 효과 프리팹 풀과 내부 미사일 뷰를 재사용한다. 적 추적과 처치 판정은 표현과 분리되어 있다. 획득 아이콘은 사용자 제공 이미지이고 발사되는 미사일 본체는 이 프로젝트에서 생성한 절차적 이미지다.

## 확인 범위

2026-11-19 밸런스 조정으로 발사 수를 5→4발, 비행 수명을 7.5→4초로 변경했다. 수명 만료 후 0.22초 폭발은 유지한다. 변경 후에는 C# 컴파일만 확인하며 Play Mode 검사는 실행하지 않는다. 아래 실제 실행 기록은 변경 전 설정 기준이다.

추가 테스트 중단 요청 전에 컴파일과 규칙 검사를 마쳤다. 실제 MainPlay의 구성된 상황에서 5발 발사, 비행 픽셀 표시, 착탄 폭발, 7기 처치와 점수 반영, 재시작 후 정리를 확인했다. 중단 요청 이후 추가 검사는 수행하지 않았다. Android 실기기, 효과음 청취와 장시간 밸런스는 확인하지 않았다.
