# 적 등장·처치 연출

`MainPlay`의 기존 `EdgeChaseWaveHost`가 자동으로 연결한다. 별도 Animator, 프리팹 또는 Inspector 참조 설정은 필요하지 않다.

적 표시 폭은 0.45, 충돌 반경은 0.15, 예고 표식 기본 폭은 0.8로 최초 크기의 1.25배다. 일반 적과 빙결된 적에 함께 적용되며 플레이어 크기는 유지한다. 파편과 처치 잔상도 적의 표시 폭을 기준으로 커진다.

- 등장 예고: 테두리 안쪽의 실제 생성 위치에서 예고 표식이 흐리게 나타나고 점점 빠르게 깜빡인다. 크기도 조금씩 커진다. 기존 예고 시간은 유지하며 예고와 실제 등장 좌표를 동일하게 사용한다. 적의 충돌 원과 가장 크게 커진 예고 표식이 모두 테두리 안에 들어오도록 여백을 둔다.
- 활성화: 0.12초 동안 크기와 밝기가 안정된다. 이동·충돌은 기존 활성화 시점부터 시작한다.
- 일반 처치: 짧은 잔상과 붉은 삼각 파편 7개가 퍼지고, 약 0.32초 동안 회전·감속·축소하며 사라진다.
- 빙결 중 처치: 얼어 있는 적 이미지와 푸른 파편을 사용한다. 쇄빙뿐 아니라 빙결 중 폭탄·보호막으로 처치해도 적용한다.
- 판정과 점수: 처치 순간 기존 방식으로 확정한다. 파편은 충돌과 점수 판정에 참여하지 않는다.
- 재사용: 파편 SpriteRenderer를 풀에서 재사용하며, 삼각 Sprite는 실행 중 한 번 생성한다. 동시에 표시할 수 있는 잔상·파편은 864개로 제한한다. 연출용 난수는 웨이브·아이템 난수와 분리한다.
- 파편 모양은 실행 중 만든 작은 삼각 텍스처를 사용한다. 기본 whiteTexture의 Sprite 영역을 넘는 OverrideGeometry 오류를 피하도록 했다.
- 재시작: 기존 적과 예고를 정리하면서 파편도 즉시 숨긴다. 플레이어 사망 후에는 남은 파편 연출만 마무리한다.

## 조정

`Enemy Waves` 오브젝트의 `EdgeChaseWaveHost > Enemy Animation`에서 깜빡임 시작·종료 주기, 활성화 연출 시간, 파편 수·지속 시간·속도를 조정한다. 파편 수는 5~8개다. 스폰 주기나 충돌 크기를 바꾸는 설정은 아니다.

`EdgeChasePattern`의 Minimum/Maximum Spawn Inset은 테두리에서 안쪽으로 떨어진 거리다. 이전 바깥쪽 거리 설정은 이 안쪽 여백으로 읽으며, 너무 작게 설정해도 충돌 원과 예고 표식에 필요한 최소 여백을 확보한다. 패턴 프로토타입의 추적·벽·포위·화살표·요격 적도 안쪽 생성 규칙을 적용한다. 벽·돌진 적이 활성화된 뒤 밖으로 나가 퇴장하는 동작은 유지한다.

## 검증 범위

Unity 6000.3.20f1의 C# 컴파일러와 프로젝트 참조로 런타임 코드 컴파일을 통과했고, 호출 연결과 재시작 정리 경로를 검토했다. 이번 변경의 Play Mode 실행 검사는 생략했다. 이전 아이템 검사 통과 기록은 이번 연출의 실행 검증을 의미하지 않는다. 실제 애니메이션의 가독성과 타격감은 사용자가 MainPlay에서 플레이하며 확인한다.

안쪽 스폰 변경은 격리된 Unity 에디터 실행에서 본편 무작위 배치 256건, 예고→활성 좌표 일치, 바깥 배치 거부를 확인했다. 프로토타입 6개 선택 항목의 생성 위치와 화살표 회전·요격 적의 초기 위치도 검사했다. 결과는 `Temp/CodexInsideSpawn/result.json`에 있다. 이 검사는 좌표와 전환 처리 검사이며 자유 플레이 검증은 아니다.
