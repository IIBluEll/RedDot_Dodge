# InGame 한 씬 전환

`InGame`을 실행하면 메인 메뉴에서 대기합니다. `GameStart_Btn`의 OnClick은 씬의 `InGame Flow` 오브젝트에 있는 `InGameFlowController.OnGameStartActioned`에 연결했습니다.

1. 시작 버튼 입력을 잠그고 인게임 Canvas를 현재 화면의 위쪽에 준비합니다. 게임 월드는 켜되 플레이어·적·아이템은 준비하지 않습니다.
2. 메뉴 제목·시작·안내·설정 버튼과 메뉴 배경이 함께 아래로 한 화면만큼 이동합니다. 동시에 HUD와 경기장도 위에서 아래로 같은 화면 거리·시간·가감속 곡선으로 내려와, 카메라가 위쪽 화면으로 올라가는 느낌을 만듭니다. 메뉴와 인게임의 투명도는 유지하며, 메뉴 Canvas는 전환이 끝난 뒤 숨깁니다.
3. 전환 완료 시 `BeginRound()`를 호출합니다. 기존 준비 시간에 연동된 3 → 2 → 1 이후 플레이어 조작과 게임 진행이 시작됩니다.

시작 전환은 기본 0.65초이며 `InGame Flow > Start Pan Seconds`에서 조정합니다. 기존 `Game Enter Seconds`는 결과 화면에서 Retry할 때의 UI 복귀 시간으로 유지합니다. UI 애니메이션은 DOTween Sequence로 묶고 게임 시간 배율에 독립적으로 진행합니다. 전환 도중 메뉴로 돌아가도 메뉴 배경과 각 UI의 원래 위치를 복구합니다.

메뉴 복귀는 시작 전환의 반대 방향입니다. 인게임 HUD·경기장은 위로 한 화면만큼 퇴장하고, 메뉴 배경·제목·버튼은 아래에서 원래 위치로 함께 올라옵니다. 기본 0.65초이며 `InGame Flow > Return Seconds`에서 조정합니다. 두 화면 모두 `InOutCubic` 가감속을 사용하고 페이드 없이 이동합니다. 결과 화면에서 복귀할 때는 숨겨진 게임 UI를 다시 켜지 않고 결과 오버레이 전체가 위로 퇴장합니다. 결과 버튼은 복귀 중 잠그며, 메뉴 도착 후 게임을 비활성화하고 UI 위치와 입력을 복구합니다. 시작 전환 중 취소할 때는 기존처럼 즉시 메뉴로 복귀합니다.

2026-11-20 시작·복귀 전환 개정은 현재 프로젝트 참조와 Unity C# 컴파일러로 런타임 코드 컴파일을 확인했습니다. 실제 전환 재생과 기기별 체감 검증은 실행하지 않았습니다.

`EdgeChaseWaveHost`는 최초 초기화와 한 판의 시작·정리를 분리했습니다. `BeginRound()`는 초기화를 보장하고 새 판을 시작하며, `StopRound()`는 적·아이템·효과·점수·예약을 정리하고 플레이어를 숨깁니다. `InGame`에서는 결과 화면의 다시 하기 버튼을 사용하고, `MainPlay`에서는 기존 R 키 재시작을 유지합니다.

`MainPlay`는 자동 시작 기본값을 유지하고, `InGame`의 호스트만 `Start Automatically`를 껐습니다. 초기 Canvas 표시와 시작 버튼, CanvasGroup, 전환 대상은 InGame 씬 파일에 연결되어 있습니다. `ReturnToMenu()`는 위치와 투명도를 복원하고 메뉴 대기로 돌아갑니다. 결과 화면의 메인 메뉴 버튼도 이 함수를 사용합니다. 메인 메뉴의 조작 방법·설정 버튼과 일시정지의 설정 버튼도 씬에 연결했습니다.

최초 메뉴 전환 작업 당시에는 컴파일 검사와 Play Mode 테스트를 실행하지 않았습니다. 아래 결과 화면 추가 작업에서 Unity 배치 컴파일과 구성된 상황의 Play Mode 검사를 진행했습니다. Unity에 이전 씬 상태가 열려 있다면 저장된 InGame 씬을 다시 불러와 사용합니다.

## 결과 화면과 로컬 최고 기록

2026-11-19 결과 화면을 `InGame`에 연결했습니다. 기존 패널·버튼·아이콘과 폰트를 사용하고, `Result_Canvas`에 별도 오버레이를 배치했습니다. `GAME OVER` 제목은 전용 `ResultTitleGlow.mat`을 사용합니다. 화면에는 최종 점수, 최대 콤보, 생존 시간(소수 둘째 자리), 처치 수와 최고 점수를 표시합니다. 신기록일 때만 `최고 기록!`을 표시합니다.

- `EdgeChaseWaveHost.FinishRound()`는 전투를 정지하고 변경 불가능한 `RoundResult`를 한 번 전달합니다. 남은 활성 적·예고 적은 기존 파편 효과로 파괴하고 아이템·잔류 효과·플레이어·트레일을 정리합니다. 사망 연출에서 제거한 적은 점수·처치 수·콤보에 더하지 않습니다. 결과 확정 후에는 전투·점수·생존 시간·콤보 타이머를 진행하지 않습니다.
- `InGameFlowController`는 `DEATH_TRANSITION → RESULT` 순서로 진행합니다. HUD는 위로, 경기장 테두리와 카운트다운은 아래로 퇴장한 뒤 비활성화합니다. 배경은 유지하고, 퇴장 중에는 경기장 UI를 추적하는 카메라를 정지해 배경과 파편 위치가 UI를 따라 움직이지 않도록 합니다. 기본 퇴장은 0.28초 대기와 0.42초 이동, 경기장 0.04초 지연을 합해 0.74초입니다. 사망 시 전체 적 파편은 기본 0.6초(개별 편차 포함) 유지하며, 일반 처치 파편의 0.32초 설정과 구분합니다. 전환 종료 시 남은 파편도 정리하고 결과창만 표시합니다.
- 다시 하기는 결과창을 숨기고 게임 UI를 0.26초 동안 원래 위치로 복귀시킨 뒤 기존 정리 로직을 거쳐 3초 준비부터 시작합니다. 카메라 추적도 복구합니다. 메인 메뉴 복귀는 진행 중 전환을 취소하므로 사망 연출 도중 메뉴로 돌아가도 결과창이 뒤늦게 나타나지 않습니다.
- `ResultPresenter_presenter`는 저장소와 결과 View를 연결하고 HUD의 BEST를 갱신합니다. 메인 메뉴에는 최고 점수를 표시하지 않습니다. `ResultPanel_view`는 숫자 표시, 등장 애니메이션과 기본 버튼 선택을 담당합니다.
- `InGame`에서는 R 키로 결과 화면을 우회하지 않도록 `_allowKeyboardRestart`를 끕니다. `MainPlay`의 기존 R 키 재시작은 유지합니다.

적·예고의 Sorting Order는 4, 적 파편은 5로 설정해 아이템 획득물(2)과 미사일 본체(3)를 포함한 현재 아이템 표현보다 앞에 표시합니다. 사망 시간과 렌더 순서 조정 후 추가 실행 검사는 사용자 요청에 따라 진행하지 않았습니다.

`PlayerPrefsScoreStorage`가 `RedDotDodge.BestScore.v1` 키에 최고 점수를 저장합니다. 점수는 64비트이므로 `SetString`과 `long.TryParse`를 사용하며 신기록일 때 `PlayerPrefs.Save()`를 호출합니다. 저장은 사망 연출 시작 시 수행하고 결과 표시만 전환 종료까지 기다립니다. 첫 실행과 손상된 값은 0점으로 읽고 동점·낮은 점수는 갱신하지 않습니다. 진행 중 메뉴로 돌아가 중단한 판도 저장하지 않습니다. 서버 DB는 아직 연결하지 않았으며, 향후 저장 처리 변경은 이 저장소와 Presenter 연결 부분에서 진행할 수 있습니다.

`RedDot Dodge > Create Result Screen`은 결과 화면을 생성하는 개발 메뉴입니다. 이미 화면이 있으면 기존 배치를 유지하고 최고 점수 표시 참조를 연결합니다. 배포 씬 목록은 변경하지 않았으므로 현재 기본 빌드 진입점은 계속 `MainPlay`입니다.

## 일시정지와 재개

`InGame`의 HUD 일시정지 아이콘에 버튼을 연결하고 `Pause_Canvas`에 기존 네온 패널·아이콘·폰트로 일시정지 화면을 배치했습니다. 이번 변경은 코드와 씬 파일만 수정했으며 사용자 요청에 따라 컴파일·Play Mode 검사와 새 테스트 작성은 진행하지 않았습니다.

- PC의 Esc와 HUD 버튼으로 준비·플레이 중 일시정지합니다. PC 포커스 이탈과 Android 백그라운드 전환에도 같은 동작을 적용합니다. 앱으로 돌아와도 자동 재개하지 않습니다. 시작 전환 도중 앱을 벗어나면 전환 완료 후 준비 상태에서 정지합니다.
- `PAUSED`에서는 `Time.timeScale = 0`으로 전투·생존 시간·준비 카운트다운·웨이브·아이템·빙결·콤보와 시간을 따르는 표현을 함께 멈춥니다. `AudioListener.pause`로 효과음을 정지하되 BGM은 계속 재생합니다. 정지 직전 값을 보관하고 재개·메뉴 복귀·컨트롤러 비활성화 시 복구합니다. BGM은 별도로 앱 백그라운드·포커스 이탈을 확인해 정지하고 앱 복귀 후 이어갑니다.
- 계속하기 또는 Esc는 `RESUMING`으로 전환합니다. 실제 시간 기준 1초 동안 전투와 타이머를 계속 정지하고 플레이어 위치에 강조 링을 표시합니다. 숫자는 게임 시작 때 쓰는 중앙 `ReadyCountdown_Txt`와 `ScoreText_view.ShowReadyCountdown()`을 재사용합니다. `ScorePresenter_presenter`가 Flow의 남은 카운트다운을 읽으므로 시작·재개 표시가 서로 덮어쓰지 않습니다. 별도로 추가했던 하단 재개 안내 텍스트는 제거했습니다. 종료 후 기존 준비·플레이를 이어갑니다. 이 도중 다시 Esc를 누르거나 앱을 벗어나면 일시정지로 돌아갑니다.
- 일시정지의 메인 메뉴 버튼은 종료 확인을 먼저 표시합니다. 취소하면 일시정지 화면으로 돌아가며 종료를 확정하면 현재 판을 정리합니다. 중단한 판은 최고 점수에 저장하지 않습니다.
- Android에는 기울기 재보정 버튼을 표시합니다. 일시정지 동안 입력 읽기는 유지하고 실제 이동만 정지합니다. 앱 복귀 시 기준 자세를 자동으로 다시 잡지 않으며, 사용자가 재보정 버튼을 누른 경우에만 현재 자세를 새 기준으로 사용합니다. 새 판 시작 시 기준 자세를 잡는 기존 동작은 유지합니다.

`InGameFlowController`는 상태·시간·오디오와 앱 전환을 관리합니다. `PausePresenter_presenter`는 View와 플레이어·카메라를 연결하고, `PausePanel_view`는 일시정지·종료 확인·재개 준비 표시와 버튼 선택을 담당합니다. 기존 HUD 버튼, 각 버튼의 이벤트와 새 Presenter 참조는 씬에 연결했습니다. 현재 에디터에서 이전 씬이 열려 있다면 변경된 `InGame` 씬을 다시 불러와 사용합니다.

## 조작 안내와 설정

`HowTo_Canvas`와 `Settings_Canvas`에 편집 가능한 UI를 추가했습니다. 기존 폰트·아이콘과 Unity 기본 UI 스프라이트를 사용합니다. 초기 안내·설정 추가 당시에는 사용자 요청에 따라 컴파일·실행 검사와 새 테스트 작성을 진행하지 않았으며, 이후 개정의 확인 범위는 아래에 구분합니다.

- 메인 메뉴의 조작 방법은 PC와 Android의 이동·일시정지 방법을 한 화면에 함께 표시합니다. 마우스·기울기 선 아이콘과 두 열의 안내 아래에 폭탄·빙결·보호막·유도 미사일을 2×2로 배치합니다. 기존 네온 테두리와 획득 아이콘을 사용하며 아이템별 버튼 모양 배경은 제거했습니다. 빙결 후 접촉 쇄빙과 연속 처치를 하단에서 강조합니다. 플랫폼에 따라 설명을 교체하지 않으며, 안내 문구와 배치는 씬에서 편집합니다. `HowToControlImage`는 두 조작 아이콘을 UI 메시로 그립니다.
- 설정은 메인 메뉴와 일시정지에서 같은 어두운 패널을 사용합니다. 작은 설정 제목 아래에 아이콘·항목명·조절 요소·현재 값을 행별로 배치하며, BGM·SFX 음량은 각각 0~100%로 조절합니다. 0%가 해당 종류의 음소거입니다. SFX는 `AudioListener.volume`에, BGM은 리스너 음량을 무시하는 전용 AudioSource의 기본 음량 × BGM 설정값에 즉시 적용합니다. 효과음 기본 음량은 최초 값 대비 50% 높였고(0.3 → 0.45), 미사일 발사·명중은 추가 배율을 적용한다. BGM 기본 음량 0.35를 유지하며 AudioMixer는 추가하지 않았습니다.
- 기울기 감도는 양쪽 플랫폼에서 표시하되 Android에서만 조작할 수 있습니다. 감도는 50~200%(기존 0.5~2.0배), 기본 100%이며 최대 이동 속도는 바꾸지 않고 같은 기울기의 입력 강도를 조정합니다. 메인 메뉴에서는 시작 시 자동 보정을 안내하고 재보정 버튼은 비활성화합니다. 진행 중 일시정지에서는 현재 자세로 재보정할 수 있습니다. PC는 웹 배포를 기준으로 하며 전체 화면·창 모드 선택과 관련 저장 처리는 제거했습니다. 설정창은 BGM·SFX·기울기 감도·언어 네 행으로 구성합니다.
- 설정을 닫으면 열었던 메인 메뉴 또는 일시정지 화면으로 돌아갑니다. Esc도 같은 닫기 동작을 사용합니다. 일시정지에서 설정을 열어도 전투·타이머·효과음 정지는 유지하며 BGM은 계속됩니다. 설정을 닫는 것만으로 게임을 재개하지 않습니다.
- BGM·SFX·감도·언어는 `RedDotDodge.Settings.*.v1` PlayerPrefs 키에 저장합니다. 설정 닫기, 앱 백그라운드 전환과 Presenter 비활성화 시 저장하고 다음 씬 초기화에서 불러옵니다. 언어는 선택 즉시 저장합니다. 새 BGM·SFX 키가 없는 경우 이전 전체 음량·음소거 값을 두 음량의 초기값으로 이어받습니다. 최고 점수 키는 사용하지 않습니다.
- 언어 행의 좌우 화살표로 한국어와 English를 선택합니다. 처음에는 한국어이며 다음 실행부터 저장된 언어로 시작합니다. 메인 메뉴·조작 안내·일시정지·종료 확인·결과·설정의 문구와 재보정 안내·신기록 문구에 즉시 반영합니다. 공통 영문 HUD 표기(SCORE·COMBO·BEST), 게임 로고와 사용자가 입력한 곡명은 그대로 사용합니다.

`SettingsModel_model`은 설정값과 저장을 담당합니다. `SettingsPresenter_presenter`는 음량과 플레이어 입력에 값을 적용하고, `SettingsPanel_view`는 슬라이더·현재 값·플랫폼별 항목을 표시합니다. `HowToPresenter_presenter`와 `HowToPanel_view`는 조작 안내를 표시합니다. `InGameFlowController`는 `HOW_TO`·`SETTINGS` 상태와 닫기·복귀를 관리합니다.

`GameLocalization`은 현재 언어와 변경 이벤트를 관리하며, `LocalizedText`는 각 TMP 텍스트의 한국어·영어 문구를 씬에 보관합니다. 활성 화면은 이벤트로 갱신하고 비활성 화면은 다음 표시 시 갱신합니다. 새 고정 문구에는 `LocalizedText`와 두 언어를 연결합니다. 실행 중 바뀌는 신기록·재보정 문구는 해당 View에서 `GameLocalization.GetText()`를 사용합니다. 별도 현지화 패키지는 추가하지 않았습니다.

2026-11-20 조작 안내 개정은 해당 Canvas와 의존 리소스를 복사한 격리 Unity 6000.3.20f1 프로젝트에서 안내 관련 코드 컴파일과 Edit Mode 렌더를 확인했습니다. 1920×1080·1280×720·2400×1080에서 텍스트 넘침 없이 두 플랫폼과 아이템 4종이 표시됩니다. 미리보기는 `ArtExports/HowToPreview`에 저장했습니다. 본편 전체 컴파일, 메뉴에서의 버튼 조작, Play Mode 및 Android 실기기 검사는 포함하지 않습니다.

설정창 개정은 프로젝트 참조를 사용한 런타임 C# 컴파일, 격리 Unity에서 기존 음량·음소거 이전과 새 설정 저장·복원, 음량 범위, BGM 초기화 순서·효과음 음량과의 독립 적용을 확인했습니다. PC·Android 표시를 각각 1920×1080·1280×720·2400×1080에서 렌더했습니다. `ArtExports/SettingsPreview`의 BGM 70%·SFX 80%는 레이아웃 확인용 예시이며 신규 설치 기본 음량은 각각 100%입니다. 버튼·드래그 입력, 음악 청취와 Android 실기기는 확인하지 않았습니다.

언어 추가는 한국어 기본값·영어 저장/복원·즉시 변경 이벤트와 중복 이벤트 방지 검사를 통과했습니다. 격리 Unity Edit Mode에서 두 언어의 PC·Android 설정창을 세 해상도로, 영문 메인 메뉴·조작 안내·일시정지·결과를 1280×720으로 렌더하고 텍스트 넘침을 검사했습니다. 미리보기와 검사 기록은 `ArtExports/LocalizationPreview`에 저장합니다. 실제 버튼 입력, 브라우저 빌드 실행과 Android 실기기 검사는 포함하지 않습니다.

## 배경음악과 곡명 알림

`Background Music` 오브젝트의 `BackgroundMusicPlayer > Tracks`에 제목과 AudioClip을 목록 순서대로 연결합니다. 메인 메뉴가 처음 표시된 뒤 2초 후 시작하며 전체 목록을 반복합니다. 첫 대기는 한 번만 적용하고 메뉴·플레이·결과 전환에도 음악을 이어갑니다. 음악은 BGM 음량 설정을 따르며 게임 일시정지 중에도 재생합니다. 앱 백그라운드·포커스 이탈 시에는 멈추고 앱 복귀 후 기존 위치에서 이어갑니다. 곡이 시작될 때 Safe Area 왼쪽 아래에 제목 알림을 표시합니다. 연결 방법과 표시 시간 조정은 [배경음악 재생 목록](BACKGROUND_MUSIC.md)에 정리했습니다. 최초 BGM 추가 작업의 컴파일·실행 검사는 진행하지 않았습니다.

## 결과 화면 확인 범위

`RedDot Dodge > Check Result Flow`에서 전용 PlayerPrefs 테스트 키를 사용해 검사를 실행합니다. 검사 후 테스트 키는 삭제하며 실제 최고 기록 키는 변경하지 않습니다. 결과는 `ArtExports/ResultQA/result.json`, 샘플 결과 화면의 실제 Unity 렌더는 `ArtExports/ResultQA/ResultPreview.png`에 저장합니다. 미리보기의 24,600점은 레이아웃 확인을 위한 샘플 값입니다.

검사는 Play Mode에서 적을 플레이어 위치에 배치하고 전투 틱과 Tween 진행을 수동 제어해 사망 결과, 적 상한 96기와 예고 정리, 아이템·효과 정리, UI 퇴장 방향·배경 유지, 3회 Retry 복원, 결과의 메뉴 버튼, 사망 전환 중단, 결과 고정과 64비트 저장·복원을 확인합니다. 자연스럽게 한 판을 진행한 플레이테스트, 실제 앱 재실행, Android 실기기와 성능 검증은 포함하지 않습니다.
